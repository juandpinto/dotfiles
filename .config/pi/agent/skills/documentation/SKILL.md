# Documentation writing guidelines

- I am a data scientist. Assume that all documentation will be read by other data scientists, but also by some non-technical stakeholders. Write documentation that is accessible and informative for both audiences
- Aim for clarity and conciseness while still being thorough
- Unless otherwise specified, write in first person plural ("we") to reflect the collaborative nature of our work. Imperative voice and passive voice where warranted are also fine
- Write headings using sentence case capitalization (only capitalize the first word and proper nouns)
- Don't split long lines with line breaks---let the text wrap naturally
- Don't use horizontal rules (`---`) to break up sections, unless there is a very clear break that can't be conveyed through headings alone (this will be rare)
- For tables, include space padding to line up columns and improve readability
- For lists, use hyphens (`-`) rather than asterisks (`*`) for bullet points
- For em-dashes (`—`) and en-dashes (`–`), don't use spaces on either side
- Unless otherwise specified, don't add a table of contents
- If citations are necessary/requested, use APA style (this will be rare)
